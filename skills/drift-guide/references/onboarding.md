# 偏航观测使用向导

这是给 AI 执行的向导。用中文，一次只处理当前路线。插件只能提供线索，不能保证发现所有偏题；规则模式尤其不能理解一句话是否偏题。不要许诺检测率、正确进度或必然暂停。

## 1. 每次先看状态

1. 从宿主插件列表、加载信息与可用命令核实 `drift-watch` 是否已安装、启用、加载，`/drift` 是否可用。Skill 可读不等于 hooks 已加载，文件存在也不等于插件在运行。没有入口时说「缺少：插件未确认加载」，引导按 README 安装或重新加载；不要声称已装好。
2. 只读当前宿主的有效配置。本仓库 marketplace 安装后实测是 `~/.claude/settings.json` 的 `pluginConfigs["drift-watch@drift-watch"].options`；本地加载可为 `pluginConfigs["drift-watch"].options` 或 `drift-watch@inline`。先从宿主报告确认当前插件键，再读取对应项；不能把另一个安装入口的设置当成本次有效值。还要核对项目、项目本地和托管设置是否覆盖，`CLAUDE_CONFIG_DIR` 有指定时用其配置目录。只展示本插件非敏感偏好，不输出整份设置、环境变量表或任何密钥。
3. 有已保存的有效选项，且用户不是要求「改设置」时，只提醒一句：「正在用上次的设置，说『改设置』可改。」然后进入用户要求的路线，不重问卷。
4. 无设置：先说明实际默认 `escalation=pause`、`judgeModel=haiku`、`logDir=""`。**没有保存偏好也会按默认运行，Haiku 可在开始任务后发起模型请求**；问卷并不会暂停插件。默认模型请求会带目标、补充、计划和最近操作摘要。用户要避免额外请求时先引导在 `/config` 关闭判断模型，再继续。不要静默改配置。
5. 配置缺失按默认处理；JSON 损坏、结构错误或值无效时标「缺少」，说明具体字段，保留原文件，不能把坏文件当空对象覆盖。只读体检直接做，不因缺设置而先强迫用户答问卷。

## 2. 首次问卷 / 改设置

优先用 `AskUserQuestion`；宿主没有这个工具，就给编号题等待回答。用户已经说清的不用再问。第一题先问路线，再只追问该路线需要的选项：

「你想用它做什么？为什么问：不同用法需要的模型和桌面功能不同。
1. 看 Claude 有没有反复打转（推荐，先用规则观察）。
2. 还想看目标、阶段和进度的模型概括。
3. 卡住时交接到干净的新会话（需要桌面会话工具）。」

用户可选多条。推荐路线只决定建议值，**不修改插件内置默认值**。

| 后续题 | 推荐项与其他项 | 为什么问 / 必须说明 |
| --- | --- | --- |
| 提醒过还再犯时怎么办？ | `pause` 暂停等你（推荐）；`remind` 继续但再提醒；`block` 拦住下一次普通工具操作先解释 | 决定插件是否中断工作。`block` 不是安全沙箱，计划工具先走原逻辑；接手会话再次卡住会暂停。 |
| 要不要让模型判断和概括？ | 路线 1：`off`（推荐，不增加插件模型请求）；路线 2：`haiku`（推荐，默认）；`sonnet` 也是可选 | `off` 保留重复、错误和计划停滞规则，进度按待办比例，没有待办就可能无百分比；不做语义离题判断。`haiku/sonnet` 会把目标、补充、计划、最近几步摘要发给模型，错误摘要也可能包含在内；有常见凭据脱敏，但不保证清除所有私人内容。可选接别家模型：确认接口格式、地址、模型名和密钥来源；只支持 OpenAI 兼容与 Anthropic 兼容格式，本地 Ollama 可不带密钥。填了自定义地址，会把这些摘要发给该地址。 |
| 航行日志存哪里？ | 默认目录（推荐，设置值空字符串）；用户指定本机绝对路径 | 日志含任务内容与文件路径。默认 `~/.claude/drift-watch/航行日志`，插件读不到 HOME 才退到插件根目录的 `航行日志/`。自定义路径必须绝对、可写；把 `~` 展开后保存，不存未展开的 `~`。 |

路线 3 还需先从**本机已暴露的工具列表**核实 `ccd_session.start_session`；分屏另需 `ccd_window.open_session_in`，卡片后备需 `ccd_session.spawn_task`。没有这些就说明「可以在原会话换思路，不能保证开侧会话」，让用户选接受降级或只用观察。不要为了探测而开会话，不联网、不登录。

模型费用必须说清：默认 Anthropic 没有用户自备 API 密钥时走 Claude Code 自带模型通道，消耗用户自己的订阅额度。如果已配置钥匙串条目或 `DRIFT_WATCH_API_KEY`，优先直连；自定义接口按对方计费，插件不另收费，失败可能退回宿主模型。OpenAI 兼容填齐 `apiBaseUrl` 和 `apiModel` 后，无密钥也会尝试直连（便于本地 Ollama）；Anthropic 的地址留空用官方接口，模型名留空沿用 haiku/sonnet 映射。`off` 完全不调用插件判断模型，但当前 AI 对话本身仍消耗正常额度。不要读钥匙串，不运行 `security`，不发测试请求，不询问密钥原值。需要自备密钥时只告诉用户自己在钥匙串或环境变量配置。

## 3. 保存偏好

向用户展示本次选定的选项（含自定义模型时的接口格式、地址、模型名和密钥条目名，绝不展示密钥原值）、实际配置文件和实际插件键，问「是否保存这些设置？」用户已明确给出同范围保存授权就继续，不重复征求。用户只说开始用、示例或体检，不等于同意持久改设置。拒绝保存可沿用当前实际值，说明本次不是临时改变默认模型。

优先让宿主 `/config` 修改本插件选项；若由 AI 写文件：

- 用宿主有效的 `pluginConfigs` 保存，不创建另一份 profile；参考 README 的完整 Python 3 合并示例，仅把用户选定值写入正确插件键。
- 写前备份原设置为同目录唯一 `.bak-*` 文件，权限 600；已有 JSON 和各层必须是对象，损坏时停止该写入。
- 合并 `pluginConfigs`、本插件对象及 `options`，保留其他插件、未知选项和所有无关键；不要用示例 JSON 替换整份文件，不输出原配置内容。
- 用同目录临时文件、权限 600、写入后原子替换，替换前核对原文件没有被他人改变；失败保留备份，清理本次临时文件。
- 读回所选值；重载或按宿主提示新开会话，核对**运行中的值**再说生效。安装时可已经存过设置，此时直接沿用。

重置前解释会清除哪些本插件选项、会恢复默认 Haiku（可能增加模型请求），日志不会自动删除。取得明确同意后才操作；不清空其他插件设置，不顺手删除日志、密钥或项目文件。

## 4. 本地体检（所有路线共用）

每项输出「可用 / 缺少 / 这条路线不需要」及中文下一步；无法验证的写「缺少：尚未核验」，不能报可用。只查本地：不联网、不验证模型凭据、不运行 `security`、不调用模型或新会话工具。

| 检查项 | 怎么查；缺少时下一步 |
| --- | --- |
| 插件已加载 | 看宿主加载信息和 `/drift` 命令；缺少时按 README 安装、启用、重载，不把磁盘文件存在当运行证据。 |
| 设置可读 | 解析有效配置，只显示本插件非敏感选项：escalation、judgeModel、logDir、apiFormat、apiModel；自定义地址先遮掉可能误填的账户密码、查询参数再展示。无设置可说明使用内置默认，格式损坏则先备份修复。 |
| 日志目录可写 | 解析实际路径；已有目录可在获准的本机目录做唯一命名空文件写入并立即删除，绝不动旧文件。权限不允许或目录尚不存在时标缺少，给出创建/授权目录的下一步，不仅凭路径存在称可写。 |
| 最近一份航行日志 | 只在实际目录找最近修改的 `.md`，读回目标节和末尾 `drift-watch:state` JSON，报告路径；不存在时说明先跑示例。除非用户请求，不把日志全文贴进聊天。 |
| judgeModel 状态 | `off`：可用（规则），模型连通性这条路线不需要；其他值：可用（设置已读），模型连接/额度未核验。仅判断密钥来源是否设置，绝不读取/显示原值。 |
| 自定义模型配置 | 不联网，只查是否填齐和地址格式：`apiFormat` 默认 anthropic，仅接受 anthropic/openai；openai 必须同时有 `apiBaseUrl`、`apiModel`，anthropic 可留空。用 URL 解析地址，只接受 HTTPS，或主机是 localhost/127.0.0.1/[::1] 的 HTTP，拒绝账户密码、查询参数和片段（`#`）。缺项/不合要求标「缺少：将退回宿主通道」，给出要补的字段；不输出原始坏地址。密钥只确认来源是否配置，本地服务可不带；`off` 时说明模型这条路线不需要。配置检查通过仍须说明「接口连通性、模型可用性、密钥与额度未核验」。 |
| 桌面与侧会话能力 | 根据当前宿主和本机工具清单核对；路线 1/2 不要因没有侧会话工具报整体失败。路线 3 缺工具时列降级路径与下一步。 |

不要为了体检运行 `/drift probe`：它会实际调用会话/窗口 MCP，体检只读本地已知信息即可。体检通过不等于真实任务已成功。

## 5. 固定免登录示例

这里的「免登录」指不登录其他网站、不配置额外密钥。本地规则示例要求插件的**有效** `judgeModel=off`，避免插件后台模型请求；用户已有其他设置时先说明并取得改设置授权，备份保存，生效后再跑。用户不愿修改就不称免额外请求，可说明后按其当前路线运行；不要悄悄切换。

1. 用系统临时目录机制新建唯一的 `drift-watch-demo-*` 目录，只在其中创建文件；不要使用固定目录覆盖旧示例。固定目标原话为：**「偏航观测固定示例：在临时目录新建 note.txt，写入 hello，再把内容改成 hello drift-watch，最后核对文件和航行日志。」**
2. 示例会重置当前面板目标/计划/步骤，但保留旧航行日志与累计统计。若当前还有未完成任务，先说明影响，优先在用户新开的空会话中运行；确认允许切换后，先通过宿主可用的命令执行入口运行 `/drift new <固定目标原话>`，再开始工具操作。没有命令执行入口就请用户输入这一行，不能自行编造已切换。**必须显式设置目标**，否则「跑一下示例」或「开始用」会成为原始目标，无法通过日志验收。
3. 用 `Write` 创建临时目录的 `note.txt`（`hello\n`），用 `Edit` 改为 `hello drift-watch\n`，用 `Read` 读回。先明确说「下面故意做一次无关操作，用来认识检测限制」，再在同一临时目录创建 `side.txt` 写入 `今天星期几与本任务无关\n`，然后回到 note.txt。所有文件只含固定示例文字。
4. 只偏题一次不保证出现提醒；`off` 不做语义判断，不能为展示强行造报错或宣称抓到了偏题。若用户还要看重复提醒，解释已有自动化测试覆盖它，不擅自反复制造失败或扩大示例。
5. 等待插件写盘（一般下一次关键更新或约 4 秒定时刷新；最多检查 3 次、每次间隔 4 秒）。在有效日志目录找本次更新的日志，读回「最初的目标」以及末尾状态 JSON 的 `goal`，两处都须等于固定目标原话；核对 note.txt 内容，报告实际路径。不直接手工生成航行日志冒充插件产物。
6. 交互桌面版须确认小条出现，并输入 `/drift` 核对面板里的目标；能观察界面就直接核对，不能时请用户回报界面结果，标「桌面显示待核验」。终端版核对文字小条/面板；无界面的 `-p` / SDK 不要求显示，标「这条路线不需要」。没有日志、目标不符、文件内容不符都不算完成，按体检定位缺口。
7. 保留已展示的示例产物，告诉用户临时目录可能被系统清理；不自动删除用户已看到的成果、不清旧日志。若用户要求还原设置，先明确要还原的三个偏好及模型影响，在已有同范围授权下合并还原，不能整份覆盖备份而冲掉后续改动。

日志文件名只有日期与目标前缀，同一天同名任务可能复用同一个文件；对比本轮运行前后修改时间与实际目标，不能拿一份旧日志算新成功。需要保留旧示例日志时先征得同意改用独立 logDir，不改代码的命名规则。

## 6. 每次收尾三样

按实际结果说，不把下面示例句当作已验证事实：

1. 「本次 note.txt 在……；航行日志在……，我读回了……。」无产物时明确缺什么。
2. 「输入 `/drift` 打开面板；接下来直接说你的真实任务。若还停留在示例任务，用 `/drift new 你的真实目标` 切换。」界面未核验也要说明。
3. 「下次可以直接说：『开始用偏航观测』、『改设置』、『体检一下偏航观测』。」

用户只要求体检时不强行跑示例；已存在设置时不重复问卷；已有明确保存授权时不重复询问。
